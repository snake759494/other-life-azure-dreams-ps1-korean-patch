# 기술 설명

## 디스크 구성

| 파일 | 내용 |
| --- | --- |
| `SLPM_860.47` | 실행파일. 0x8002E800에 올라감 |
| `MAIN/MAIN.BIN` | 공통 데이터(타이틀, 아이템 설명, 옵션 등) |
| `TOWN/TOWN.BIN` | 마을 데이터(대사, 장소 이름, 그림) |
| `DUNGEON/DUNGEON.BIN` | 탑 데이터(던전 메시지, 몬스터 도감, 그림) |
| `STR/LOP2_WS.STR` | 오프닝 무비(자막 포함) |

패치는 파일 크기와 위치를 바꾸지 않습니다. 대신 바뀐 섹터만 다시 쓰고 Mode2 Form1의 EDC/ECC를 다시 계산합니다(`tools/disc.py`, `tools/cdsec.py`). 그래서 결과 BIN은 원본과 크기가 같습니다.

## 문자열

- 텍스트는 Shift-JIS(cp932)입니다. `0x0A`는 줄바꿈이고, `FE 00`은 주인공 이름 자리입니다. `tools/extract.py`가 네 파일에서 연속된 SJIS 구간을 모아 중복 없이 `text/segments.json`(원문과 위치 목록)을 만듭니다.
- 번역은 원문 자리에 그대로 덮어씁니다. 따라서 바이트 수, 줄 수, 줄 폭을 넘을 수 없습니다(`tools/chk.py`). 남는 자리는 다음처럼 채웁니다.
  - 뒤가 널인 문자열: `0`
  - 그 밖의 문자열: 전각 공백 `81 40`
- ASCII 숫자·영문·기호는 전각으로 바꿔 게임 글꼴로 그립니다(`tools/kenc.py`).
- 짧은 한자 라벨(장소 이름 등)은 포인터 표 바로 뒤에 붙어 있는 경우가 많습니다. 그래서 「4바이트 정렬이거나 앞이 널이고, 뒤가 널인 정확한 일치」만 바꿉니다. 이름 입력 표 영역은 제외합니다.
- 던전 메시지는 별도의 문자표 모드로 저장됩니다(`tools/dmsg.py`).
- 몬스터 도감은 10자짜리 줄 조각을 역순으로 저장한 형태입니다(`tools/ency.py`).
- 이름 입력의 「한자」 모드 표(그룹 머리글자, 칸 라벨, 끝 코드)를 한글 음절표로 바꿨습니다.

## 한글 글꼴

이 게임은 한자를 PS1 BIOS ROM의 한자 글꼴(16×15 1bpp)로 그립니다. 글리프 주소는 BIOS 함수 `Krom2RawAdd`(B0:51)로 얻습니다.

- **코드 배정**: 번역에 쓰인 한글 1,113자를 가나다순으로 SJIS 한자 코드 `0x8940`부터 배정합니다. 이름 입력에서 가나다순으로 보이게 하려는 것입니다.
- **후킹**: 실행파일의 `Krom2RawAdd` 호출 스텁(0x8006CD48)을 후킹 코드로 점프시킵니다. 배정 범위 안의 코드면 후킹 코드가 한글 글리프를 돌려주고, 그 밖의 코드는 원래 BIOS 함수로 넘깁니다.
- **배치 공간**: 글리프(26바이트 × 1,113)와 코드는 실행파일 끝 쪽에 둡니다. 구체적으로 이중 패킷 버퍼 각각의 끝 0x5000바이트입니다.
  - 버퍼 오버플로 검사 한도(0x8003C520, 0x8003C530의 `lui/addiu`)를 그만큼 낮추고, 실행파일 로드 크기를 늘려 부팅 때 함께 올라가게 했습니다.
  - 데모 화면 등에서 패킷이 한도를 약 3KB 넘겨 쓰는 경우가 있습니다. 그래서 한도 뒤에 0x1400바이트 여유(GUARD)를 두고 그 뒤부터 씁니다.
- **글리프**: 갈무리11 12px를 원본 크기 그대로 1bpp로 그립니다. 늘이거나 줄이지 않습니다(`tools/font.py`). 호출자마다 쓰는 형식이 달라서 후킹 코드가 돌려주는 모양도 다릅니다.
  - 이름 입력 표(0x800537AC)는 16폭을 1:1로 씁니다. 원본 비트를 가운데에 놓아 돌려줍니다.
  - 대화창·메뉴 변환 루틴(0x80050948)은 11열을 12폭 4bpp 텍스처로 옮깁니다. 이 루틴은 이웃 픽셀 무늬를 보고 점프 테이블로 테두리 색(1·2·3·5·6·8)을 섞습니다. 원래 글꼴에 없는 무늬나 빈 글리프를 주면 멈출 수 있습니다. 그래서 이 루틴과 그 밖의 호출자에는 원래 BIOS 글꼴처럼 펼친 글리프를 줍니다.
- **대화창 출력 보정**: 변환 루틴을 부르는 곳(0x80051E28)을 감싸기 코드로 바꿨습니다.
  - 감싸기 코드는 변환이 끝난 뒤 한글이면 출력 텍스처(행당 6바이트 × 15행)를 원본 비트로 다시 씁니다. 글자는 색 4, 나머지는 0입니다. 그래서 테두리 섞임 없이 글꼴 픽셀이 그대로 보입니다.
  - 감싸기 코드는 스택을 쓰지 않고 고정 저장 영역을 씁니다. 이 경로는 스택이 작은 곳에서도 불리기 때문입니다.
  - R3000의 로드 지연 슬롯에 주의해야 합니다. `jal` 지연 슬롯에서 읽은 레지스터는 호출된 함수의 첫 명령에 반영되지 않습니다.

## 그림 글자

그림 글자는 실행파일의 압축 루틴(0x8003F560) 형식으로 압축된 TIM 텍스처입니다(`tools/klz.py`). `tools/gfxedit.py`가 이 텍스처를 풀고, `tools/gfxspec.py`의 사양대로 일본어 글자 자리를 한글로 다시 그린 뒤 원래 압축 길이 안에 다시 압축합니다. 팔레트는 바꾸지 않고, 원본이 쓰는 색 인덱스(글자색, 테두리색 등)를 골라 그립니다. 같은 텍스처가 여러 파일에 사본으로 들어 있으면(`tools/gfxhash.json`) 사본도 함께 바꿉니다.

## 오프닝 무비 자막

`LOP2_WS.STR`은 PSX STR v2 형식입니다. 자막은 영상 아래쪽에 그려져 있으므로, 자막 구간의 프레임에서 아래쪽 매크로블록 행만 풀고 다시 인코딩합니다(`tools/mdec.py`, `tools/str.py`, `tools/mov.py`). 다시 인코딩한 행에는 한국어 자막을 그려 넣고, 프레임 섹터 크기 안에 들어가게 맞춥니다. 자막 구간의 위치 정보(`tools/movie_segs.json`)는 원본 영상에서 만든 자료라 저장소에 넣지 않았습니다.
