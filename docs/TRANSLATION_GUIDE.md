# 아더 라이프 애저 드림스 번역 지침

모든 명령은 저장소 폴더에서 실행합니다(`PYTHONIOENCODING=utf-8` 권장). `text/`의 원문·번역 파일은 저장소에 없습니다. 아래는 자신이 가진 원본으로 다시 만들 때 쓰는 형식입니다.

## 파일
- 원문: `text/ja/bNN.json` = `[{"id", "ja", "bytes", "lines", "maxw"}]` (게임 데이터 순서대로 정렬. 앞뒤 블록이 이어지는 대화인 경우가 많으니 문맥을 보고 번역)
- 번역: `text/ko/bNN.json` = `[{"id": n, "ko": "..."}]` — 원문의 **모든 id**를 같은 순서로. UTF-8, `ensure_ascii=False`로 저장(파이썬으로 json.dump 권장).
- 검사: `python tools/chk.py bNN` → 마지막 줄이 `문제 블록: 0 / N`이 될 때까지 고친다.

## 절대 제약 (원문 자리에 덮어쓰므로)
1. **바이트 수 ≤ `bytes`**: 한글·공백·기호·숫자·영문 모두 1글자 = 2바이트, 줄바꿈 `\n` = 1바이트, `{N}` = 2바이트. 남는 자리는 빌드 도구가 자동으로 채운다.
   - 한국어가 길어지기 쉬우니 **간결하게 의역**한다. 띄어쓰기도 2바이트이므로 꼭 필요한 곳만 띄우되, 읽기에 어색할 정도로 붙이지는 않는다.
   - 말줄임은 `…`(1글자)를 쓴다. `・・・`/`...`도 자동으로 `…`로 바뀐다. 원문 `・・・・・・。`처럼 긴 침묵은 `……` 정도로.
2. **줄 수 ≤ `lines`**, **한 줄 글자 수 ≤ `maxw`** (`{N}`은 4글자로 계산). 줄바꿈 위치는 자유롭게 바꿔도 된다(문장 중간 어색한 곳은 피함).
3. `{N}`(주인공 이름)은 원문과 **같은 개수**. 
4. 행 머리의 전각 공백 `　`(대사 들여쓰기)은 가능하면 유지. 단, 바이트가 모자라면 빼도 된다.
5. 쓸 수 있는 문자: 한글, 숫자, 영문, 공백, `.,?!~-()[]「」『』…・♪☆★○●×%:/` 등. **일본어 가나·한자는 남기면 안 된다.** `‰`(하트 기호)는 원문에 있으면 그대로 둔다.
6. 선택지 `［…］`는 대괄호를 유지(`[ ]` 반각으로 써도 됨). 
7. 깨진 데이터처럼 보이는 블록(의미 없는 한자 2~3자, 예: `ル蔭`, `セ郡`)이나 개발용 메모(`＠（…）` 줄)는 **원문 그대로** `ko`에 복사한다(그러면 빌드 시 손대지 않음). 단 메모 줄과 실제 대사가 한 블록에 섞여 있으면 메모 줄은 아주 짧게 번역하거나 `＠`만 남기고 줄여도 된다(표시되지 않는 메모).

## 번역 원칙
- **기계 번역 금지.** 스스로 문맥을 보고 자연스러운 한국어로 번역한다.
- 사투리: 오사카 사투리(〜や, 〜やん, 〜へん 등) 캐릭터(예: 팬/잡화점 여자 등)는 경상도/부산 느낌의 가벼운 사투리로 살려도 좋다(과하지 않게).
- 말투: 원문의 반말/존댓말/노인 말투(〜じゃ → 〜구먼/〜라네), 아가씨 말투(〜ですわ → 〜이랍니다/〜해요) 등을 살린다.
- 고유명사(아래 용어집)를 반드시 통일. 용어집에 없는 가타카나 고유명사는 일본어 발음 그대로 국립국어원 표기에 가깝게 적되, 영어 원어가 분명한 일반 명사는 한국어 관용(예: エビフライ 새우튀김, カジノ 카지노, プール 수영장, ボーリング 볼링, カレー 카레).
